### 1.（已完结）计划正文是英文，界面其他地方是中文

**现在**：命令工作台右键处置、SFTP 文件操作的对话框里，"将要执行"和"出错后如何还原"
两栏显示的是英文，例如
`change /usr/local/lib/pyshared/.helper permissions from 4755 to 0644 only if the captured mode still matches`。

**为什么**：这句话是核心层生成的，它就是核心承诺要执行的那条操作。翻译成中文之后，
界面上写的和实际执行的就不再是同一句话；万一译歪了，操作员看到的承诺和机器做的事对不上，
这在处置场景里比"英文难读"更危险。目前的折中是给它套了中文标签栏。

**改的话**：要么让核心直接生成中文摘要（`crates/lovelyhawk-core/src/operations.rs` 一带的
`summary`/`restore_description`），这样界面和执行仍然是同一句；要么在渲染层做一层**受控**
翻译——只翻已知的固定句式，遇到没见过的句式原样显示，绝不猜。我倾向第一种。

**进展（2026-08-27）**：Docker 容器动作那条路按第一种改法做了——
`build_action_plan` 的摘要、五条回滚说明、以及验证回执的 `observed container state: ...`
都改成核心直接生成中文，界面照原样显示，仍然是同一句话。摘要里的容器 id 也从 64 位全长
换成运行时自己那种 12 位短 id（完整 id 留在操作日志的元数据里，审计需要它）。

**已完结（2026-08-28）**：剩下两处一并按第一种改法做完了。
`crates/lovelyhawk-core/src/sftp.rs` 的 `mutation_description` 与 `operation_description`
（十条 mutation 加解压、上传）现在由核心直接生成中文。命令工作台那两个处置动作不需要单独改——
「去掉执行权限」build 出来的是 `ChmodIfMode`、「隔离」是 `Remove`，两者都走这同一个函数，
所以它们的确认文案跟着一起变了。

钉子是 `every_plan_sentence_is_written_in_the_language_of_the_window`：逐条 mutation 断言
摘要与回滚说明里有中文，并且不再出现 `atomically`、`SHA-256`、`captured`、`namespace`
这些操作员没法据以行动的实现词。**本条目关闭。**

### 18.（已处理 2026-10-11）后端调用排队执行，长操作期间终端输出会卡住

**当时**：宿主把每次后端调用放进一条先进先出的队列。实测（`ui/scripts/probe-terminal-during-long-task.mjs`，

**当时**：系统关闭（Alt+F4、任务栏右键关闭）、主窗口关闭时一并关掉子窗口、断开或切换连接时回收子窗口，

**现在**：编辑窗口把“有未保存的修改”告诉宿主（`file_editor_unsaved`）。此时来自页面以外的关闭请求会被拦下，
宿主用与主窗口相同的带编号请求去问这个窗口（`child_close_decision`），窗口弹出与自己的关闭按钮相同的确认。

### 5.（已完结 2026-09-04）"已遮蔽"这类提示恒为 0，而且是句假话

**原来**：全局移除内容遮蔽之后，围绕它的文案没清理，于是核查审计页挂着一个永远显示
**0 遮蔽字段**的计数块，还有一句"credential-like 字段已遮蔽，隐藏范围不表示安全"。

被同一个"已遮蔽"混在一起说，所以那边改成分开讲。

**为什么这条值得做**：在一个用来读证据的工具里，告诉操作员"有内容被藏起来了"是最坏的方向——
它让人**不再往下看**。而这句话当时还不是真的。

**验收**：靶机实测两台真机 baseline 108 项 0 处 redacted、审计各计数全 0；
`tools/lab/probe-ui-baseline.mjs` 新增一段在真实窗口里逐页断言"不出现已遮蔽、不出现恒 0 计数"，
ubuntu/rocky/alpine 三台通过。

**还留着的**：DTO 里 `redacted`/`redactedFieldCount` 字段本身没删（契约冻结，删它要动两个 API
的 exact 键集、门禁与大量测试）。已在两处常量上写明它是"冻结的标志"而不是决策，
渲染层也有断言保证没有任何页面再读它。真要清干净是另一件独立工作。

### 24. 命令列表、目录列表到期后不会自己续上（2026-10-11）

**已处理一部分（2026-10-11）**：三个页面都按到期时间提前标出“已过期”，而不是等点了运行才报错。
命令工作台：到点后列表标为已过期、运行按钮停用、“重新加载”突出显示，每次成功运行都会重新计时
（后端本来就按使用续期）。命令审计：到点后标为已过期，不再发出会被拒绝的采集和日志读取，依赖列表的
按钮停用并提示先“刷新命令列表”。SFTP 文件管理：后端改为每次读取目录都重新计时
（原先只按打开时间算，一直在浏览也会到期）；到期或后端答复浏览已失效时，底部写明“目录列表已过期”，
“刷新”换成突出的“重新打开”（从起始目录重新读取，下载进行中时不可用），上传、下载、删除、新建、
打包、在这里打开终端以及右键菜单的操作都先停用并说明原因。
**又处理一部分（2026-10-13）**：SFTP“重新打开”后回到原来所在的文件夹，不再回到起始目录。过期的入口仍然
一律拒绝（这是安全边界）；页面记下从起始目录一路进来的文件夹名，新的文件管理读出起始目录后逐层进入
“名字完全相同且只有一个”的文件夹，每一步都是新列表里的普通读取。中途某层已被删除、改名、无权查看，或者有两个
显示成同名的，就停在那一层并写明原因；名字被截短或超过 32 层时不记路径，重新打开后从起始目录开始并说明。
探针 `ui/scripts/probe-sftp-expiry.mjs` 在 lab-super 上 9 项通过（三层临时目录，过期后重新打开回到最深那层）。
仍未做：到期前自动续期。

**原来**：命令工作台、命令审计和 SFTP 目录都显示"命令列表 / 目录列表约 N 分钟内有效"，
悬停说明到期后点"重新加载"或刷新即可；到期后再运行会被拒绝，提示"操作入口可能已过期"。
这一行原先写的是"能力约 N 分钟有效"，是实现用语，已改成说人话。数字是读取时算的，不会倒数。

**为什么**：列表里的每一项都绑定读取时的目标和会话，过期拒绝是安全边界，不能放宽；
自动续期要处理正在运行的检查、已选中的项和目标切换，这一轮只改了文案。

**改的话**：重新读取会换一套新句柄（`catalog-started` 还会清空已显示的结果），而结果里的
文件操作入口绑定旧列表，所以不能悄悄续期——那样会让还在屏幕上的结果的操作在背后失效。
较稳的一步是到点时在页面上明确标出“列表已过期”、停用运行按钮并突出“重新加载”，而不是
等用户点了运行才报错；真要续期，需按分类与标题对应新旧命令、保留选中项，并让旧结果的操作
入口同时说明已过期。

### 26.（已处理 2026-10-13）再次双击程序，已开的窗口不会回到前面

**原来**：程序开着时再双击 `LovelyHawk.exe`，第二个进程拿不到 `data` 目录的实例锁就退出。Windows 上会弹一个
“LovelyHawk 已经在运行……请切换到已打开的窗口”的提示框（最初记这条时误写成“没有任何反应”，那是非 Windows
分支的行为），已开的窗口不会被带到最前，最小化着的还得自己去任务栏找。

**现在**：第二个进程在 `data` 目录里建一个固定名字的请求文件（`.lovelyhawk-show.request`）后最多等 3 秒；
正在运行的那个每 0.3 秒看一次，看到就删掉它，把主窗口从最小化还原、带到最前并把键盘交给页面，
应用日志记一行 “a second launch asked for the window”。请求文件的内容从不读取，不能用来传路径、打开文件或
任何参数，别的本机进程能做到的最多是让窗口出现在前面。3 秒内没人接（运行中的那个卡住或还在启动），
请求撤回、仍弹原来的提示框。没有新增依赖，也没有新的 `unsafe`。
做的时候发现：还原后立刻调 show()，窗口还没意识到自己已不是最小化，会被重新收回任务栏；现在只在需要时
还原，等 150 毫秒再置前。
**验证**：`crates/lovelyhawk-desktop/src/instance_lock.rs` 单测（请求只被取一次、没人取时撤回不留文件）；
真实进程探针 `ui/scripts/probe-single-instance.mjs` 9 项通过：最小化后第二次启动 0.2 秒内自行退出、没有提示框，
窗口被还原并置前，请求文件不残留，两次请求都记进日志，仍只有一个主窗口。页面是否拿到键盘只记录不断言
（这台电脑有人在用时，前台归属由 Windows 和使用者决定）；无人干扰的那次观察到页面拿到了键盘。

### 16.（已完结 2026-09-04）busybox 机器上，三张最关键的表是空的，而且说的是"没有发现"

**做法**：把 `find -printf` 全部换成 `find … -exec stat -c '%a|%U|%s|%y|%n' {} +` 再交给 awk 拼列
（`crates/lovelyhawk-core/src/system_info.rs` 的 `file_facts_awk!` 宏）。三处细节都是有原因的：
`stat -c` 是可移植的那一半（busybox 没有 `--printf`）；`-exec … {} +` 成批调用，一次 stat 覆盖几百个
文件；**路径放在最后一个字段**，这样名字里带竖线也不会被切开，awk 再把它拼回去；制表符由 awk 的
`printf` 生成，因为 `stat -c` 不解释转义（第 21 轮刚在这上面栽过）。
一并换掉的还有六处明细命令（用户家目录的 setuid 与近期改动、`/etc/sudoers.d` 列表、
`~/.ssh` 私钥元数据、"附近的备份候选"、进程 fd 列表），它们是同一个毛病。

### 16. busybox 机器上，三张最关键的表是空的，而且说的是"没有发现"

**现在**（2026-09-04 实测，lab-alpine）：SUID 文件、敏感文件、最近修改文件这三张表都靠

```
# lab-alpine
$ find /bin /sbin /usr/bin /usr/sbin /usr/local/bin -xdev -type f \( -perm -4000 -o -perm -2000 \) -printf '%p\t%m\n'
find: unrecognized: -printf

$ find /bin /usr/bin -xdev -type f -perm -4000        # 换个写法就有
/bin/busybox
/usr/bin/passwd
/usr/bin/expiry
```

### 15.（已完结 2026-09-04）删掉的 webshell 还留在 web 根目录里，而且还能访问

**结论**：走的是下面第 2 条加第 3 条，不是我原先倾向的第 1 条。把"挪出 web 根"这件事想透之后
不能那么做：备份是靠 `rename` 挪的，跨文件系统必然失败，而复核要求备份存在——所以在
`/var` 与 `/var/tmp` 分属不同挂载点的机器上，**删除会直接失败**，那是比留个副本更糟的结果。

- 备份名字后面加 `.removed`（`crates/lovelyhawk-core/src/sftp.rs` 的 `BACKUP_SUFFIX`）。

- 备份目录 0700、备份文件 0600（`BACKUP_DIRECTORY_MODE` / `BACKUP_FILE_MODE`），

  能不能删由复核说了算。
- 计划文案改成把落点说出来："把 /var/www/html/evil.php 挪进同目录下的 `.lovelyres-backups/`
  留底：名字后面加 .removed、权限收成只有你能读，网站再也跑不动它（不是直接抹掉）"。
  （`.lovelyres-backups` 这个目录名改名后仍沿用，以兼容目标机上已有的备份。）
  原文案只说"移进可恢复的备份区"，从没说过副本就在同一个目录里——而那正是 web 根时最该说的一句。

**顺带修的两处**：撤销删除现在会把**权限也还原**（`RestoreToken::RemovedToBackup` 多带一个

### 12.（已完结 2026-09-04）表是空的，分不清"这台机器没有"还是"我没看成"

**现在**（2026-09-04 发现）：主机全景每个标签页的命令都写着 `2>/dev/null`。工具不在的时候

**为什么要紧**：对应急场景，"防火墙一条规则都没有"和"这台机器上没有 iptables，我看不了"
是**完全相反的结论**——前者意味着门户大开、要立刻处置，后者意味着还得换个办法去看。

### 11.（已完结 2026-09-04）主机全景的表在目标机上就被截到 500 行，界面却说没截断

### 9.（已完结 2026-09-04）sshd_config 的 Match 块没有被识别

**原来**：基线扫描按"第一条未注释的设置"读 sshd_config，这对文件顶层是对的，
