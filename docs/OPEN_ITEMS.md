# 待办与已知粗糙处

这里记的是**已经做完、能用，但留了口子**的小事：等你拍板的取舍、暂时够用的做法、
以及做的时候顺手记下的坑。跟 `UNWIRED_FEATURES.md` 分开——那份记的是"实现了但没接线"，
需要正式验收证据；这份记的是日常里随手能改掉的东西。

格式：一条一个问题，写清**现在是什么样**、**为什么当时这么做**、**改的话要动哪里**。
做掉一条就删一条。

---

## 等你决定

### 1. 计划正文是英文，界面其他地方是中文

**现在**：命令工作台右键处置、SFTP 文件操作的对话框里，"将要执行"和"出错后如何还原"
两栏显示的是英文，例如
`change /usr/local/lib/pyshared/.helper permissions from 4755 to 0644 only if the captured mode still matches`。

**为什么**：这句话是核心层生成的，它就是核心承诺要执行的那条操作。翻译成中文之后，
界面上写的和实际执行的就不再是同一句话；万一译歪了，操作员看到的承诺和机器做的事对不上，
这在处置场景里比"英文难读"更危险。目前的折中是给它套了中文标签栏。

**改的话**：要么让核心直接生成中文摘要（`crates/lovelyres-core/src/operations.rs` 一带的
`summary`/`restore_description`），这样界面和执行仍然是同一句；要么在渲染层做一层**受控**
翻译——只翻已知的固定句式，遇到没见过的句式原样显示，绝不猜。我倾向第一种。

### 2. "下载留证"没做

**现在**：右键菜单只有查看属性 / 去掉执行权限 / 隔离三项。

**为什么**：下载要打通本地保存路径和系统另存为对话框，跟现有这几个纯远端 RPC 不是一类
东西，得多一条主进程的文件写入链路。文件管理器那边已经能下载，所以不是缺功能，只是少个近路。

**改的话**：新增一个 `emergency-command.path.download`，走 `sftp` 的 `download` 加
主进程的 `showSaveDialog`，preload 从 116 变 117，门禁/探针/边界测试跟着改。

### 3. 打包出来的 exe 还是 Electron 的默认图标

**现在**：便携版可执行文件的图标没换成 LovelyRes 自己的。

**为什么**：换 Windows exe 图标要在打包后用 `rcedit` 改资源段，当时优先做功能了。

**改的话**：打包脚本里加一步 `rcedit`，图标源文件要一起进仓库并纳入门禁的固定资产清单
（`scripts/electron-source-gate.ps1` 里的 pinned assets）。

## 暂时够用

### 4. "已遮蔽 N 行"这类提示现在恒为 0

**现在**：全局移除内容遮蔽之后，采集类输出一律原样显示，所以凡是"已遮蔽 N 行"的提示
永远显示 0，等于一句废话。

**为什么**：移除遮蔽那次改动只动了行为，没顺手清理围绕它的文案。

**改的话**：把这些提示整段删掉，连同它们的三处断言一起（改文案要同步 3 处断言，见
`feedback_ui_copy_style`）。需要先扫一遍还有哪些页面在显示这类提示。

### 5. AI 相关能力有意没接线

**现在**：AI 分析、AI 历史等入口在多个页面上都被刻意留空。

**为什么**：线下纯防御修复赛是离线环境，AI 调用要么打不通、要么把现场数据发出去，
两种都不能接受。这是设计决定，不是遗漏。

**改的话**：除非明确要做联网场景，否则不动。真要做，必须先有"离线时完全静默、
不发起任何外连"的证据。

### 6. 计划有效期显示成"300 秒"

**现在**：处置对话框里写"计划有效期 300 秒"。

**为什么**：跟 SFTP 那边的对话框保持一致，那里也是秒。

**改的话**：两边一起改成"5 分钟"，只改一边会更乱。

## 做的时候记下的坑

### 7. 没有 systemd 的主机上找不到中间件

**现在**：中间件发现靠 `systemctl list-unit-files` 列服务单元。容器、精简安装、
非 systemd 发行版上根本问不出来。现在会明说"这台主机没有 systemd，改到命令工作台按进程
和端口查"，而不是报"调查失败"，也不会报"一个都没找到"。

**为什么**：报"没找到"是假阴性——综合靶机上正跑着 nginx、MariaDB、Redis、PostgreSQL
四个服务。宁可说问不出来，也不能说没有。

**改的话**：加一条非 systemd 的发现路径——按监听端口 + 进程可执行文件反查产品，
再顺着产品的默认配置路径找配置文件。核心里 `middleware.rs` 已经有每个产品的路径知识，
缺的是"从进程认出产品"这一步。这个缺口在 `crossdistro_support_status` 记忆里也记着。

### 8. sshd_config 的 Match 块没有被识别

**现在**：基线扫描按"第一条未注释的设置"读 sshd_config，这对文件顶层是对的，
但 `Match Address 10.0.0.0/8` 块里的设置只对匹配的连接生效，扫描会把它们当成全局值。

**为什么**：修注释行那次改动只解决了"注释被当成设置"和取值顺序，Match 是另一层语义。

**改的话**：`sshd -T` 会直接给出 sshd 解析后的有效配置，比自己解析可靠得多，
而且这 11 项 sshd 基线全能受益。代价是要 root、配置有语法错时会失败，需要一条
"`sshd -T` 不可用就回退到自己解析"的路径，并且明确告诉操作员用的是哪一种。

### 9. 靶机首次识别偶发超时

**现在**：`tools/lab/probe-ui.mjs` 跑过一次 `timed out waiting for the catalogue`，
重跑就好了。靶机识别的期限是 15 秒（`DETECTION_DEADLINE`），容器负载高的时候会擦边。

**为什么**：识别超时已经会回退到通用命令集而不是报错，所以不算故障；但目录加载本身
还是慢到让 UI 探针的等待窗口不够用。

**改的话**：如果实机上也遇到"打开命令工作台要等很久"，再考虑把识别结果按 target
缓存起来，而不是每次绑定都重新探测。
