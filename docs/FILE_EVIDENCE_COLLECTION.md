# 应急文件下载留证

命令工作台的调查结果中，具有文件操作入口的路径可选择“下载留证”。查看采集说明后点击“选择目录并留证”，系统目录选择器确定本机保存位置。应用创建独立的 `LovelyHawk-evidence-<UUID>` 文件夹（早期版本创建的是 `LovelyRes-evidence-<UUID>`），显示下载与复核进度，完成后关联到采集开始时当前主机的案件。没有打开的案件时自动创建。

每个文件夹包含：

- `sample.bin`：原始文件字节，不进行文本解码、脱敏或换行转换，不自动打开或执行。
- `manifest.json`：来源连接身份、主机、账号、端口、SSH 主机公钥指纹、原始和规范路径、文件大小、权限、UID/GID、修改与访问时间观测、采集开始/结束 UTC 时间、SHA-256，以及方法限制。
- `README.txt`：完整性验证与未完成采集的识别说明。

采集失败、取消或断连可能留下不完整的 `sample.bin`。只有清单能完整解析、样本摘要匹配且采集流程确认完成，才能作为已完成留证使用。文件和清单已经保存、但案件记录写入失败时，界面明确提示“尚未进入报告”，保留文件供后续处理。

## 采集方法与边界

通过现有绑定的 SSH/SFTP 会话采集，不要求远端安装 Python、哈希工具或额外服务，不改变远端权限、内容或服务状态。读取可能改变访问时间，并产生磁盘和网络负载；应用不会回写访问时间。

1. 解析调查输出产生的文件能力，核对目标和会话；不接受界面提供的任意远端路径。
2. 要求规范绝对路径、普通文件、已报告文件类型与大小；拒绝符号链接及经过符号链接目录的路径。特殊文件和大小不可靠的伪文件系统内容不属于本入口的支持范围。
3. 分块下载并计算摘要，检查打开文件的属性；重新打开原路径独立读取，核对内容摘要及属性；回读本地文件核对第三个摘要。
4. 任一观测出现大小、模式、UID/GID、修改时间、规范路径或摘要差异时拒绝完成；原始与最终访问时间分别记录。
5. 写入完整清单后将外部文件摘要登记到指定案件。相同内容来自不同采集目录或来源时分别保留，不能只按摘要合并来源。

这是两次远端观测和一次本地回读的一致性验证，**不是原子文件系统快照**。SFTP 不提供可信 inode 或整个时间段内持续不变的证明，也不能防止不可信服务器伪造。具体限制随清单保存。

当前单文件上限 **512 MiB**，采集期限 **15 分钟**，使用 64 KiB 缓冲区。每个连接最多一个进行中的任务，全局最多四个任务；任务记录保留最多 20 分钟。取消与断连会终止读取，迟到结果不能发布成功清单。任务状态和进度不会携带原始文件内容或本机绝对路径。

本机文件使用独立随机目录和 `create_new`，拒绝覆盖已有文件，不按远端文件名创建本机路径，不自动递归清理用户所选目录。Unix 新目录使用 0700、文件使用 0600；Windows 继承所选位置的访问控制。原始证据可能敏感，应按实际案件要求保管与分析。

## 抓包留证

网络抓包页的“抓包并保存…”沿用同一套留证：按页面上选的网卡、过滤条件、包数和秒数在目标上运行一次 tcpdump，把结果存成 `capture.pcap`（可用 Wireshark 打开），放进系统目录选择器选定位置下的新 `LovelyHawk-evidence-<UUID>` 文件夹，并登记到开始时的案件（证据类型为抓包）。

1. 页面只交出网卡的句柄和有界参数（1–300 秒、1–100000 个包、不含换行的过滤条件）；本机目录由宿主的目录选择器决定，不经过页面。目标上的文件路径由 core 生成：`/tmp/lovelyres-pcap-<UUID>.pcap`（沿用旧前缀，便于识别旧版本留下的文件），页面和请求都不能指定。
2. tcpdump 需要 root 或免密码 sudo；没有 tcpdump、`timeout` 或 `sha256sum`、或 sudo 需要密码时，在开始前说明原因，不安装任何东西。tcpdump 拒绝（例如过滤条件写错）时，页面给出固定的说明，并把 tcpdump 自己的最后一行作为纯文本引用；目标上不留下文件。
3. 抓包结束后，目标上先计算文件大小和 SHA-256；然后按上一节的方法两次读取、本地回读，三个摘要和目标上算出的摘要必须一致，才写入清单。清单在 `capture` 一节记录工具、网卡、过滤条件、包数与时长上限、抓包开始与结束时间（UTC）、目标上的大小与摘要、临时文件路径以及它是否已删除。
4. 读回后删除目标上的临时文件，并如实报告是否删除成功。取消时先中断命令行里带有这个临时路径的进程（路径含新的 UUID，只会是这次抓包的 timeout、sudo 与 tcpdump），再删除文件并核对它已不存在；不使用 `pkill`/`killall` 之类按名字匹配的方式。
5. 超过 512 MiB 的抓包文件不留存，在目标上删除并提示缩短时长、加过滤条件或降低包数上限。

限制：文件只包含内核在这段时间交给 tcpdump、且符合过滤条件的数据包；内核丢包数没有记录，不代表这段时间的全部网络活动。抓包写入目标的 `/tmp` 并占用其空间。中途断开连接时任务随连接结束，目标上的 tcpdump 按设定时长自行停止，临时文件无法删除，会留在 `/tmp`。离开抓包页会取消正在进行的抓包留证。

## Pod 文件留证

Kubernetes 页面 Pod 行的“文件”对话框里，每个普通文件都有“留证”，查看过的文件也可以在查看页“把这个文件留证…”。它沿用同一套留证：原始字节存成 `pod-file.bin`，放进系统目录选择器选定位置下的新 `LovelyHawk-evidence-<UUID>` 文件夹，并登记到开始时的案件（证据标题“Pod 文件留证”）。

1. 页面只交出 Pod 列表的句柄、这个 Pod 的某个容器名（或默认容器）和文件的绝对路径；后端先按句柄解出列表里的那个 Pod，容器名不属于它就不开始。本机目录由宿主的目录选择器决定，不经过页面。SSH 主机上的临时文件路径由 core 生成：`/tmp/lovelyhawk-podfile-<UUID>.bin`，页面和请求都不能指定。
2. 复制前重新读取 Pod（同一 UID、未在删除、正在运行，所选容器正在运行），并在容器里算一次文件的长度和 SHA-256；符号链接、目录、设备拒绝，缺失的文件和超过 512 MiB 的文件不复制。没有 pods/exec 权限时用 `kubectl auth can-i` 确认后明确说明。
3. `kubectl exec … cat` 把原始字节写入主机临时文件：以 `umask 077` 和 `set -C` 独占创建（不跟随事先放好的链接），kubectl 带有这次复制专属的环境变量标记。复制后主机上算一次长度和摘要，再在容器里算一次；三者必须一致，否则删除副本并报告“复制期间文件有变化”。
4. 然后按第一节的方法两次 SFTP 读取主机副本并回读本地文件，摘要都必须与容器里的一致才写入清单。清单的 `pod` 一节记录 kubeconfig 上下文、命名空间、Pod 名与 UID、容器、路径、复制时间（UTC）、容器里的长度与摘要、主机临时文件路径及是否已删除。
5. 读回后删除主机临时文件并如实报告。取消时先结束环境变量里带有这次标记的进程（只会是这次复制的 kubectl），再删除文件并核对它已不存在；不按进程名匹配。关闭文件对话框会取消正在进行的留证。

限制：这不是原子快照，两次核对之间的变化无法排除，读取可能改变文件的访问时间；记录的是这个容器在这一刻看到的文件，不区分镜像层与卷，也不代表其他副本里的同名文件。需要 pods/exec 权限，容器里需要 sh、cat 与 sha256sum（无 shell 的镜像不能留证）。复制期间文件经过 SSH 主机的 `/tmp` 并占用其空间；中途断开连接时任务随连接结束，主机上的临时文件可能留下。

## 案件与报告

证据记录包含来源、保存位置、采集时间和 `external-artifact` 摘要范围。当前最多 30 个活动案件，每个案件最多 500 条证据和 1000 条时间线；达到上限时拒绝新增，不会淘汰旧案件或证据。采集期间切换案件不会把结果记到新案件；原案件不可写或保存失败时保留本机文件并报告关联失败。案件创建、归档选择、证据检索与笔记快照已进入 [案件工作台](CASE_WORKSPACE.md)；离线案件库、归档与恢复已接线；采集占用期间不允许结案或归档。结案和重新调查保留全部原始证据、旧时间线和明确的人工结论，重新调查不会改变当前采集归属；归档永久移除与转交继续推进。

状态栏“处置报告”会包含当前目标的活动案件与证据。只有证据、没有处置操作的案件也可生成有效报告。Markdown / HTML 包含文件来源、采集说明、保存位置和摘要；原始样本字节不进入报告。报告是生成时的固定快照，后续采集完成后需要刷新。报告不重新读取外部文件，转交前仍需按清单复验副本摘要。

## 复现与验收

先构建最新后端和桌面应用，再运行独立探针。它只使用本次创建并逐次核对身份的 WSL/Docker 容器，不重建现有靶机或导入用户连接库。

```powershell
cargo build --locked --package lovelyhawk-backend --bin lovelyhawk-backend
pnpm ui:check
pnpm desktop:build
node tools/lab/probe-file-evidence.mjs
$env:EVIDENCE_LAB = 'alpine'
node tools/lab/probe-file-evidence.mjs
Remove-Item Env:EVIDENCE_LAB
```

探针检查真实 SSH/RPC、二进制副本、来源清单、重复内容的不同来源、报告关联、符号链接拒绝、大小限制和取消。Ubuntu 运行另走真实桌面应用 CDP 的按钮、进度、结果、焦点、最小窗口和报告，并检查独立 HTML 的排版。**仅系统目录选择器的返回值由测试替换为专用目录**：Electron 时期经本次测试进程的 main debugger 替换，并用隐藏的 Electron 窗口检查 HTML；Tauri 调试构建改由 `LOVELYHAWK_TEST_DIALOG_ANSWERS` 提供，发布构建不含此钩子。其余部分使用正常应用入口和真实实现（Electron 时期为 RPC、主进程 IPC、沙箱 preload、React 界面及文件采集；现为宿主命令、页面桥接层、React 界面及文件采集）。这不构成操作系统目录选择器的人工交互验收，严格发布台账不能因此放宽。

当前已记录的实验结果均来自 Electron 时期，具体版本见 `PRODUCT_ROADMAP.md`。容器内 SFTP 能力不代表整个发行版、宿主内核、其他架构或全产品兼容通过。超过单文件限制的采集、目录批量取证、快照取证、案件完整生命周期、外部文件重新导入和跨案件转交仍需继续实现。
