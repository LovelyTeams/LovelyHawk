## 加载环

实际 WebView2 返回 `prefers-reduced-motion: reduce`，而应用设置为
`data-motion="full"`。旧全局样式仍将动画时长改成 `0s`、执行次数改成一次，
导致 SSH 等任务显示静止的环。

七类活动指示器现在共享任务反馈样式：普通模式每 0.8 秒旋转一圈，Windows
减少动态效果模式改为每 1.8 秒、12 个离散步骤；用户在应用中关闭界面动画时，
改用每 2 秒的缓慢明暗反馈。装饰动画继续遵守关闭和减少动态效果设置。

## 测试 SSH 配置后保存

后端只有在 SSH 测试成功且 `commit_probe` 完成后才报告 `probe-succeeded`。
旧页面没有同步这个已保存状态，导致新建连接再次走创建接口并因 ID 重复报错。

页面现在切换为更新已有连接，明确提示“验证通过并已保存”，重新读取保存视图、
更新列表并清空已保存的口令草稿。回读失败时说明配置已保存但读取失败，不再
错误地继续创建。测试失败和取消仍保留原有处理。

## GitHub Release 更新

右下角版本按钮读取宿主的真实构建版本；状态栏隐藏后入口位于侧栏。点击时才
检查固定仓库 `LovelyTeams/LovelyHawk`，不在启动时静默请求网络。

- 优先读取 GitHub 最新稳定发布 API；匿名 API 限流或读取失败时，使用同一仓库
  的 `/releases/latest` 重定向和固定便携包命名确认版本及附件。
- 按版本号比较，拒绝预发布和降级。Windows x64 下载要求同时存在
  `LovelyHawk-<version>-windows-x64.zip` 和对应 `.zip.sha256`。
- 页面只提交动作和宿主签发的下载标识，不接收本机路径、通用 URL 或文件内容。
  子窗口没有更新命令权限，宿主再次核对主窗口身份。
- 检查总时限 30 秒；下载总时限 180 秒、最大 128 MiB，显示进度并支持取消。
  HTTPS 重定向仅允许 GitHub 与其发布附件 CDN。
- 校验完整大小、校验文件中的文件名和 SHA-256 后，才将内容写入用户通过系统
  对话框选择的位置。先写同目录临时文件，再以禁止覆盖的方式提交；失败不留下
  目标位置的部分安装包。
- 下载成功不等于完成安装。界面明确要求先保存编辑、结束任务并关闭应用，
  解压替换程序文件、保留 `data/`，并建议备份旧版目录。

当前交付的是便携包检查、下载和校验流程。应用内自动替换运行中的程序、
更新包签名发布链、自动重启与回滚，以及其他平台包的更新仍未实现；SHA-256
是发布附件完整性校验，不是独立发布签名。

## 工具链与构建

已固定 Rust 1.99.1、Node 26.13.0 LTS；Node 由 pnpm 的 `useNodeVersion`
为项目脚本准备，不覆盖机器上原有的 Node 安装。包管理器保持 pnpm 10.28.2。

本次更新包括 Tauri Rust 2.12.5、Tauri npm API/CLI 2.12.4、对话框插件 2.8.4、
剪贴板插件 2.5.0、React/React DOM 19.3.1、Vite 8.3.5、Vitest 5.0.5、
Tokio 1.54.1、serde_json 1.0.154、UUID 1.29.0、rfd 0.17.2 和 flate2 1.1.10。
两个锁文件、CI、依赖门禁、打包检查和第三方声明同步更新。
SSH 和终端库的跨版本接口迁移不在这次升级范围内。

开发构建将工作区优化级别设为 0、调试信息设为行号；仅对 russh、ring 和
alacritty_terminal 保留较高优化，替代原先对全部依赖启用最高优化的配置。
release 优化和静态 CRT 要求不变。Rust 1.99 对弃用原子 API、固定大小分块、
排序和受检除法的新提示采用等价写法适配，没有降低警告门禁。

日常使用 `pnpm dev`（`desktop:hot` 的别名）：启动时增量构建宿主，前端改动通过
Vite 热更新；Rust 改动后重新启动。`pnpm desktop:dev` 仍用于嵌入页面的调试构建。
首次更换工具链或依赖需要重新编译，不能拿它与缓存命中的构建直接比较。

本机记录：升级后的首次调试构建为 1 分 50 秒；后续一次宿主增量构建为
10.52 秒，无源码变化的缓存构建为 0.46 秒。计时报告在
`target/cargo-timings/`。这些是本机对应缓存状态的观察，不是全量构建提速比例；
热更新模式的页面修改不触发 Rust 编译。

## 主机全景采集、Shell 快速编辑与文案清理

删除了系统概况、检查结果和配置相关页面里重复的常驻解释，包括容量颜色、
每核负载经验阈值及“这不等于出了问题”一类文案。保留实际错误、缺少工具、
采集截断、未保存内容和危险操作确认；空结果表述为本次采集未返回条目。

主机全景的采集上限可选 500、1,000、2,000、5,000、10,000 行。
远端命令、core、快照注册表和页面契约共同处理扩大后的请求，界面每页展示
100 行。搜索与复制针对整批已采集结果，页码和筛选条件变化不会把复制范围
缩到当前页。结果截断时显示真实状态，并在可扩大范围时提供重新采集入口。
仍保留命令输出、单元格、快照与响应大小限制，10,000 行不是无限量采集。

Shell 配置按文件分组，文件标题旁提供“编辑文件”。宿主从有效快照的行记录
解析并校验路径，页面不提交任意远端路径。现有采集范围包括 `/etc/profile`、
`/etc/bash.bashrc`、`/root/.bashrc` 和有效用户名对应的 `/home/*/.bashrc`。
空文件也保留入口。编辑器独立读取文件，不把列表的一页当作文件内容；
重复打开复用窗口并保留草稿。快速编辑使用独立文件访问记录，打开或重开终端
文件浏览器不会使其保存记录失效。

保存沿用计划、明确确认、原内容摘要检查、备份及回读验证。
准备确认、执行和回读期间冻结编辑缓冲区，避免后续输入被回读覆盖。
取消保存、取消关闭或因外部修改拒绝写入时保留草稿。原有完整性边界仍生效：
超过编辑器读取范围、读取不完整、内容经过转换或不符合文件类型要求时，
不能把显示出来的片段保存成整个文件。文件回读通过只证明文件写入结果，
不代表 Shell 配置已在新会话生效或业务已恢复。
