# Nginx TLS 与 HTTP 连接复核

更新日期：2026-09-08。入口为“配置 → 修补已有配置 → 选择 Nginx 实例 → TLS 连接复核”。此功能补充 [配置修补与恢复](NGINX_PROCESS_REPAIR.md) 的运行观察，不改变修补确认、备份或恢复规则。

## 用户流程

1. 点击“读取监听端口”，选择该主进程实际持有的 TCP 端口。端口列表不预判其中哪些服务使用 TLS。
2. 填写期望的站点域名或 IP，以及以 `/` 开头的 HTTP 路径。域名不包含协议或端口；中文域名使用 Punycode。路径不接受查询参数、片段、空格和请求头，默认 `/`。
3. 点击“开始连接复核”。工具从目标主机本机分别尝试 TLS 1.0、1.1、1.2、1.3，显示协议、证书和 HTTP 的独立观察。IP 名称用于证书 IP 匹配；DNS 名称同时用于 SNI 和证书名称匹配。
4. 完成的观察自动进入复核开始时能核实的当前案件；没有当前案件时创建案件。结果明确区分“已留存”和“尚未留证”，支持展开或复制完整记录、查看留证案件。无法读取本机案件时仍展示连接结果，并说明重试保存会使用届时的当前案件。
5. 修补或恢复后重新读取监听端口、再次复核。旧观察仍保留在案件中；页面清除旧结果，避免误认为新站点已检查。未保存结果先重试或明确放弃，再开始新操作。用户主动离开页面、切换目标或断连时先等待正在进行的复核；意外断连后的迟到结果仍失效。

这是只读探测，会产生 TCP/TLS 连接及适用的 HEAD 请求，目标可能记录访问日志。产品不会安装工具、配置 CA 信任、调整服务端密码套件、发送认证凭据或跟随重定向。

## 结果含义

| 观察 | 已取得的证据 | 不能推断的结论 |
| --- | --- | --- |
| 接受旧协议 | 以准确 TLS 1.0 或 1.1 完成握手 | 未校验证书，不发送 HTTP，不能视为可信或健康连接 |
| 明确拒绝此版本 | 服务端返回明确的协议版本拒绝告警 | 不代表其他版本、地址或站点安全 |
| 握手已完成 / 已校验 | TLS 1.2 或 1.3 握手完成，目标客户端依据其默认信任库完成证书链及站点身份校验 | 不含证书撤销检查或业务数据验证 |
| 证书校验失败 | 客户端证书验证失败，未发送 HTTP | 不能把证书错误说成服务端已禁用此协议 |
| 本机无法测试 | Python TLS 模块、协议或客户端能力不可用 | 不能判断服务端是否接受该版本 |
| 未能判断 | 超时、连接失败或其他握手失败 | 密码套件不匹配、EOF、客户端认证失败等不能伪装成旧协议已关闭 |
| HTTP 状态码 | 证书校验通过后的 HEAD 请求取得首个合法 HTTP/1.0 或 1.1 状态行 | 200 不代表所有业务健康；403、404、405、重定向及 1xx 需结合请求预期解释 |

每次必须得到四个对应版本的完整结果，拒绝缺项、重复、顺序错误或互相矛盾的数据。只保留状态码、公开叶证书 SHA-256 和固定结果码，不返回响应正文、Cookies、任意原因短语、秘密配置或握手密钥。结果时间取自本机 core 完成读取的时钟；不是目标声明的时间。

## 案件留证与失败恢复

core 生成完整观察记录，使用案件的 `Snapshot` 证据种类、`nginx-tls-http/v1` 来源和独立观察编号。记录包括原始 SSH 主机地址/端口/账号、完成时间（UTC）、Nginx 版本、PID/启动时钟/进程指纹、监听与连接地址、网络命名空间/socket inode、站点和路径、目标 TLS 客户端版本、全部四行协议结果、原因码、HTTP 状态及已验证叶证书摘要，并保留方法和范围说明。记录最多 4096 字符，超限拒绝留证，不截断后标成完整。没有 HTTP 正文、认证凭据或密钥日志。

案件归属在远端复核前取得，采集期间复用案件占用保护。完成后保存到这个明确案件，不能因为当前案件后来改变而移入另一案。同一份待存材料重试可去重，不重复加入证据或时间线；再次发起复核有新的观察编号，即使结果相同也分别保存。保存时间与原观察完成时间分开保留。

存储不可读、写入失败、案件已关闭或容量已满时，连接观察仍可读，页面不会显示留证成功。已确定案件的重试保持原归属；若最初未能读取案件，页面明确提示重试会使用当时的当前案件，没有当前案件则新建。重试只保存 core 缓存的原材料，不重新发起 TLS/HEAD，也不接收前端提供的案件编号、来源、正文或摘要。案件满时不删除旧证据，应复制完整观察并另建案件重新复核。

未保存材料仅在本次连接的有期限缓存中保留，不是持久待办队列。5 分钟无操作、连接失效或应用关闭后可能无法重试；页面仍在时可展开/复制原记录。新读取、修补和输入替换不能静默覆盖它，离开与关闭握手先等复核结束，再提供明确放弃或取消。意外退出后的待存恢复尚未实现。

记录使用现有 `stored-preview` 摘要范围，校验记录正文及其元数据，不能当作原始网络包摘要。公开叶证书 SHA-256 与案件记录 SHA-256 分别展示。案件 Markdown/HTML 报告保留完整观察；断开连接后仍可在本机案件库查看并导出完整 JSON。更改连接库名称或后来修补不会改写历史来源。案件及报告操作见 [案件工作台](CASE_WORKSPACE.md)。

## 目标身份与范围

沿用默认 Nginx 进程发现的 Python 3.9+、Linux pidfd、根目录/挂载命名空间及权限前提；连接复核还要求目标进程与 SSH 助手位于同一网络命名空间。

通过 `/proc/<pid>/fd` 的 socket inode 与该网络命名空间的 TCP/TCP6 LISTEN 表关联地址。IPv4 与 IPv6 按 procfs 原生 u32 字序解析。通配监听使用同协议族的 loopback 地址连接，具体监听使用其固定本机地址；不根据站点名称解析或连接任意远端 IP。链路本地地址缺少接口范围时拒绝猜测。

每次探测前后重新核对监听 inode 和命名空间，并在整个远端操作前后核对进程身份。其他非本实例 socket 的地址/端口重叠时保守拒绝，包括可能接收 IPv4 的 IPv6 通配监听；这可能拒绝实际设置了 `IPV6_V6ONLY` 的独立双栈配置，不能把这种拒绝记为不安全。主进程持有的多条监听可以属于同一实例，不能据此将 worker 的共享 socket 误判为其他服务。

观察反映目标本机的连接路径，不证明公网、负载均衡或其他网络命名空间可达，也不证明目标内核及网络转发未遭篡改。当前不覆盖 QUIC/HTTP3、Unix socket、Stream 中非 HTTP 的业务协议、客户端证书认证、复杂 Nginx 启动方式及全部发行版/架构。

每目标最多缓存 64 个监听，缓存复用既有 5 分钟期限与完整 SSH 会话身份；重新发现、读取配置或执行写入会撤销旧监听。远端限制进程、FD、TCP 表和输出大小；每个 TLS 尝试约 4 秒，整个 SSH helper 最长 45 秒。缺少权限、超限或归属变化返回无法复核，不返回部分成功结论。

## 实现与验证

复用既有 `nginx.repair` 的 `listeners` / `probe` 意图及 `retain` / `discard-observation` 保存恢复意图，未新增主窗口 API 方法（Electron 时期该总数为 128）。探测请求只能带监听句柄、期望站点名称和 HTTP 路径，不能提交目标地址、端口、CA 文件、跳过验证标志或命令；保存重试及放弃仅接受本次观察标识。core 保存真实监听、进程和待存材料；页面桥接层 `ui/src/host/main-api.ts` 直接使用 shared 契约 `isNginxRepairRequest` 校验请求后再交给宿主。

Python 构建独立 `SSLContext(PROTOCOL_TLS_CLIENT)`，现代版本加载默认信任库并限制准确协议版本。旧协议仅在本次客户端上下文放宽密码选择以观察接受情况。`SSLKEYLOGFILE` 不会启用密钥日志；不能使用会自动读取该变量启用日志的便利构造函数。依据：[Python 3.9 SSLContext 与默认上下文](https://docs.python.org/3.9/library/ssl.html#ssl.create_default_context)、[SSL 错误分类](https://docs.python.org/3.9/library/ssl.html#ssl.SSLError)、[Linux proc TCP/TCP6 格式](https://docs.kernel.org/networking/proc_net_tcp.html)。具体协议支持依赖目标 Python/OpenSSL 构建，3.9 是接口能力下限，不能表示所有 Python 版本都已实测。

运行方式复用 `node tools/lab/probe-nginx-repair.mjs`，须先构建最新 backend 和桌面应用（`pnpm backend:harness`、`pnpm desktop:build`）。探针仅在自己创建的容器中安装依赖、生成证书和临时 CA 信任，测试真实原生页面的自签证书拒绝、可信证书、主机名不匹配、HTTP 404、IPv6、普通 HTTP 端口、修补/恢复后的协议变化和旧监听失效。OpenSSL 客户端继续提供独立协议观察。具体版本、结果、截图和剩余限制见 [产品进度](PRODUCT_ROADMAP.md)。

尚未完成：意外退出后的待存队列、修补计划与前后观察的自动关联、带接口预期的业务验证、外部客户端路径和更广兼容矩阵。仅已收到案件保存回执的观察可标成已留证，不能据此自动判定业务恢复。
