# Nginx 全面可视化配置契约

LovelyRes 面向应急响应比赛环境。这里的“全面可视化”不是把某个 Nginx
版本的指令写死成一组表单，而是保证任意配置内容都有安全、可逆的编辑路径。

## 能力分层

1. **快捷模板**：为静态站点、反向代理等高频场景提供类型化表单。
2. **通用语法树**：展示并编辑任意简单语句、嵌套块和注释；保留顺序、重复项、
   引号、转义、变量以及未知或第三方指令。
3. **原文兜底**：第三方模块可以在块内嵌入 Lua、ModSecurity 规则等非 Nginx
   语言。无法可靠结构化的正文必须作为可见的原文字节区域保留，不能猜测重排。

通用编辑器不使用指令白名单。`http`、`stream`、`mail`、`map`、`geo`、
`types`、`split_clients` 和第三方模块都通过相同的语句/块模型呈现。已知指令的
专用表单只是辅助，不得成为可编辑范围的边界。

## 保真与安全边界

- 未修改文档的读取与保存必须逐字节一致，包括 UTF-8 BOM、LF/CRLF、末尾换行、
  空白、注释、引号和反斜杠。
- 编辑名称、参数或注释时，输入必须只生成一个预期节点；不能借助 `;`、`{`、
  `}`、`#` 或换行越过节点边界。
- 删除块必须原子删除整棵子树；移动只能发生在同一父块的兄弟节点之间。
- 配置正文、凭据和令牌不能出现在 `Debug`、日志或错误信息中。
- 输入大小、节点数量、参数数量和嵌套深度必须有硬上限；预览可以截断，复制和
  保存必须使用经验证的完整内容。
- 本地另存为使用独占创建，不覆盖现有文件。生成器不隐式修改远端配置。

## Include 与目标能力

`include` 是文件图边界，不应把展开结果写回单个文件。普通上下文中的 include
可以引入完整语句或块；`map`、`geo` 等上下文还可以引入表格行片段，因此后续
多文件编辑必须保留每个来源文件和调用上下文。

可用指令取决于 Nginx 版本、编译参数、动态模块和第三方模块。静态 schema 只能
提供提示，不能证明候选配置适用于比赛目标。目标侧验证必须采集 `nginx -V`，并
对候选文件运行真实二进制的 `nginx -t`；未执行时界面必须明确标记为未验证。
`nginx -T` 可用于诊断有效配置，但不得用展开输出覆盖原有 include 文件组织。

## 发布验收

- 覆盖 main/events/http/server/location/upstream/if/map/geo/types/
  split_clients/stream/mail 和未知第三方节点。
- 覆盖引号内的 `#;{}`、`${variable}`、正则、转义空格、空字符串、多行参数、
  重复指令以及自定义块正文。
- 覆盖格式错误、非 UTF-8 区域、4 MiB 文件、节点和深度上限；失败必须闭合且不
  泄漏正文。
- 导入取消或失败不能替换现有草稿；页面停用后到达的异步结果必须作废。
- 真实 Linux VM 的 `nginx -t` 矩阵未运行时只能记为 `NOT_RUN`，不能宣称通过。
