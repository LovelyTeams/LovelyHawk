# 案件工作台

从“调查 → 案件工作台”进入“当前主机”或“本机案件库”。连接主机后创建案件、查看证据、记录调查经过、整理 IOC 线索和生成报告；断开连接仍可在案件库查看、导出、结案、重新调查、归档和恢复案件。新手可以从“添加调查记录”开始；已有证据可按内容、来源、路径、摘要或记录编号检索，时间线提供关联证据和线索入口。

## 案件归属

- “当前主机”按核心目标身份（当前连接记录的身份）隔离，需要有效 SSH 连接；同一个地址的另一条连接记录不会自动共享案件。“本机案件库”是独立本地入口，可查看本机各连接的已保存案件，不赋予这些连接的远端操作权限。
- **正在查看的案件**和**当前归档案件**分开。点击案件列表只浏览；“设为当前案件”才改变后续开始的采集归属。新建案件会设为当前案件，已经开始的采集仍归原案。
- 添加调查记录、线索和关联笔记写入明确选定的案件，不跟随其他操作改变的当前案件。已结案案件可查看、检索和报告，不能继续写入。
- 创建请求有持久化的一次性请求标识；重试返回原案件，不再次切换归档案件。同一标识不能换成其他名称或目标。相同手工记录、同一笔记版本和重复 IOC 按核心规则去重。

已接通创建、查看、选择、证据/IOC/时间线检索、手工记录、笔记快照、报告，以及离线案件库、结案/重新调查、归档与恢复。改名、永久移除归档、外部案件导入和跨案件转交仍未提供界面入口；不以当前工作台宣称完整案件生命周期完成。

## 结案与重新调查

在正在查看的活动案件选择“结案并记录结论”，填写调查结论和尚待处理事项，核对完整记录后确认。结论最多 1024 个 Unicode 字符，后续事项最多 512 个，均须填写；没有待办时明确填写“无”。“当前主机”入口会在本机案件库打开这个被查看的案件，不采用另一个当前采集案件。此操作保存本机调查记录，不执行远端修补。

- 结案是人工调查判断，不证明主机已修复或恢复安全。案件全部证据、线索和旧时间线保留，新增带时间、来源 `case-disposition` 和操作编号的结案记录。若此案是当前采集案件，清除该选择；其他案件的采集归属不改变。结案仍占活动列表名额，可随后归档。
- 已结案案件停止新增证据和线索，仍可查看、生成报告、导出和归档。“重新调查”要求说明原因和后续计划，保留原结案记录并新增时间线事件，允许继续写入，但不会自动选为当前采集案件。
- 归档副本不可修改；需要改变状态时先恢复到活动列表，再生成新计划。恢复后的结案状态和历史记录完整保留。
- 状态变更使用 core 不可变计划、5 分钟一次性确认、操作日志和完整案件回读核对。内容、状态或此案是否为当前采集案件发生变化，以及文件采集尚未结束时，拒绝旧计划。时间线已满时拒绝整个变更，不删除历史腾出空间。操作日志保存内容摘要承诺；完整结论保存在案件时间线及其导出中。
- 确认展示全部结论和后续事项；完整确认超过 7 KiB 时明确要求缩短，不截断后执行。长内容可聚焦并用键盘滚动，标题与按钮保持在窗口内；阅读区域按回车不会执行。取消确认保留输入，未保存内容参与切换案件、页面、模式和关闭窗口的编辑保护。

## 离线案件库与归档

案件库按标题、案件编号、保存的连接标识和当前连接库名称搜索，可筛选活动案件与已归档版本，每页显示 25 项。连接名称明确标为**现值**，不可用时仍可查看案件；历史主机、文件属性与来源以各条证据及原始清单为准。

归档和恢复使用 core 不可变计划、5 分钟有效的一次性确认、操作日志及独立核对。确认内容包含案件名称、证据/线索/时间线数量和具体影响。归档前复查内容摘要、当前案件选择和文件采集占用；正在采集时等待完成或取消，再重新规划。关闭页面撤销未确认计划，执行期间阻止离开，失败后不能重试旧确认。

- 归档完整保留案件内容，先以独占创建方式写入 `data/case-archives/<uuid>.json`，刷新文件并按最终文件名回读、核对字节摘要和清单，再更新 `data/cases.json` 的归档索引并释放活动列表名额。归档当前案件会清除该选择，后续新采集可另建案件。
- 恢复把所选版本放回活动列表，保持原案件编号；已有同编号活动案件或列表已满时拒绝恢复。保留不可变归档原件，也不自动设为当前采集案件。同一案件后续再次归档形成另一个版本。
- 归档不是结案，也不移动或删除外部证据文件。创建请求重试仍识别原案件；原案已归档时提示从案件库恢复，不能静默创建重复案。
- 每次打开只读固定版本。完整 JSON 导出使用该版本，包含案件全部记录和清单，最多 32 MiB；文件目标仅由桌面宿主的系统保存对话框提供，独占创建并回读核对，不覆盖同名文件。返回界面的是文件名、字节数与 SHA-256，不含本机绝对路径。外部文件字节需另行交接；JSON 不是包含全部原始样本的证据包，也没有外部导入入口。

归档副本和索引属于两个文件，尚不提供跨文件断电事务。如果副本已保存而索引写入失败，原活动案件保留，并可能留下未入索引的完整副本；不会因一次错误自动删除不确定的副本。文件刷新与回读核对不能声明已通过断电恢复实验。归档文件缺失、字节被改动或清单不匹配时拒绝打开和恢复；索引保留以便排查。归档永久移除、孤立副本修复和导入仍待实现。

## 记录与证据

调查记录保存为 `note` 证据并加入时间线。标题最多 256 字，正文最多 4096 字；保存后保留为独立记录。手工 IOC 最多 2048 字，是待调查特征，不会自动执行检测或作为入侵结论。

关联 Notes 时，先选择并核对完整正文和更新时间。核心比较所选版本的摘要，随后把该版本正文保存到案件，来源为 `case-note-snapshot`，位置为 `note:<id>@<revision>`。笔记后来编辑不会改写案件内容；版本过期拒绝关联，超过 4096 字拒绝整篇关联，界面说明需要先拆分，不静默截断。

证据详情区分 `stored-preview`（存储的记录内容及相关元数据摘要）和 `external-artifact`（外部原始文件摘要）。手工输入不能伪造原始文件 SHA-256、采集来源或处置回执。原始文件仍存放在下载留证时选定的目录，报告不包含文件字节。

## 视图、容量与报告

| 项目 | 当前边界 |
| --- | --- |
| 案件数量 | 本机全部目标合计最多 30 个活动案件，已结案案件也占名额；归档释放名额，最多保留 200 个归档版本 |
| 本机持久化 | `cases.json` 编码后的读写上限 64 MiB；每份归档 / JSON 导出最多 32 MiB；超出时拒绝，不截断旧记录 |
| 每案记录 | 证据 500 条、IOC 500 条、时间线 1000 条；新增证据/IOC 连同时间线作为一次保存，容量不足时均不写入 |
| 搜索与分页 | 每页 25 条；搜索覆盖当前固定快照的完整内容、来源、位置、摘要与编号；不按不断变化的列表翻页 |
| 固定案件视图 | 5 分钟有效，同一连接新视图替换旧视图；最多 4 个视图，单个 32 MiB、合计 64 MiB |
| 离线案件视图 | 独立的 1 个固定视图，最多 32 MiB、5 分钟；目录最多 230 项，计划最多 1 个，新视图撤销旧视图与计划 |
| 报告 | 现有固定报告缓存规则；Markdown / HTML 每种最多 512 KiB，超过时明确失败 |

案件工作台“生成此案报告”使用正在查看的固定案件快照，包含该主机已记录的处置日志，不偷偷选择该案件。Markdown / HTML 完整保留各条时间线的详细内容、来源、记录编号及关联证据、线索和操作编号，包括人工结案结论、未解决事项及重新调查原因；内容按纯文本导出。状态栏“处置报告”仍汇总当前归档案件。报告主机名称取自建立连接时保存的主机、账号与端口，不使用界面传入的名字，也不随着连接库编辑改变本次来源。

更新案件后需要刷新视图再生成新报告。保存报告由桌面宿主打开系统文件选择并独占创建，不覆盖同名文件。记录和远端内容以纯文本呈现，包括恶意 HTML/Markdown。编辑中切换案件、离开页面、换主机或断开时有保留输入的交互；迟到结果不进入新目标。主机意外改变时草稿保留并禁止发往新主机。

## Nginx 连接观察

[TLS/HTTP 连接复核](NGINX_CONNECTIVITY.md) 完成后自动保存完整 `Snapshot` 证据，来源为 `nginx-tls-http/v1`，并加入案件时间线。采集前已核实的案件保持固定归属；记录保留当时的主机、进程、监听、站点、UTC 时间、四种协议的观察及限制，不使用后来编辑的连接名称替代来源。每次新复核分别记录，同一份材料的保存重试不会重复入案。

本机保存失败不会丢弃页面的连接结果，也不会显示已留证。重试仅补存原材料；最初无法取得案件时，页面明确说明重试使用届时的当前案件。只有明确放弃后才能用新操作替换未保存结果。已保存观察可从连接页面打开对应案件，进入固定快照报告和完整离线 JSON 导出；记录摘要指案件正文及元数据，不代表原始网络包或业务恢复。未保存材料尚无跨退出的持久队列。


归档永久移除与孤立副本修复、外部导入、超过当前上限的分卷导出、大档案检索性能、跨主机关联、闭环处置自动关联、目录批量采集和其他架构/系统矩阵仍待实现与验收。当前测试不替代严格发布台账。
