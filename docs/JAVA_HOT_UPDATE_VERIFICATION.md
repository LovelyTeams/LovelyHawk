# Java 热更新的范围与验证

“Java 热更新”替换某个 Java 进程所用 JAR 里的单个类文件。它只改磁盘上的 JAR，不重启、不附加到进程，也不改动运行中 JVM 已加载的类：进程要重启后才会用到新类，页面和回执都这样写明。重启与业务复核由操作员按业务要求完成。

## 流程

1. **扫描（只读）**：列出运行中的 Java 进程（PID、用户、CPU/内存、已运行时间、命令行前 512 字节）、`java -version` 和七个 JDK 工具是否可用。已退出但未被回收的进程（状态 Z）不列出：判断依据是进程状态，不是命令行文字，因为命令行可以被进程自己改写。
2. **找到 JAR（只读）**：
   - 命令行里写明的 JAR：`-jar`、`-cp`/`-classpath`/`--class-path`、`-javaagent:` 后面的绝对路径；命令行被截断时最后一个片段不算。
   - 进程正打开着的 JAR：读 `/proc/<pid>/fd` 的链接，每个进程最多 256 个，整次扫描最多提供 512 个。通配类路径（`lib/*`）、应用服务器自己加载的 JAR 都靠这一项找到。只有 root 或进程所属账号能读，读不到时页面写明“只列出命令行里写明的 JAR”；列不全时也写明。
   - 按路径打开：操作员输入的绝对路径，必须以 `/` 开头、以 `.jar` 结尾，不能含 `..`、空段、反斜杠、控制字符或首尾空格（页面与后端各查一次）。core 再拒绝符号链接和非普通文件。用于列表里没有的 JAR，例如 Tomcat 会关闭暂时不用的 `WEB-INF/lib` JAR。
3. **打开 JAR（只读）**：大小、SHA-256、类文件数与类列表（超过 500 个时只列前 500 个并写明）。
4. **选择替换文件**：由宿主的系统打开框选择本机 `.class` 文件；页面只拿到文件名、大小和 SHA-256，拿不到本机路径。文件必须以 Java 类文件的魔数开头，最大 16 MB。
5. **生成计划**：再读一次 JAR 和这个类的当前哈希，写进不可变计划；计划 10 分钟内有效，焦点在“取消”。取消的计划作废，不能再执行。
6. **确认并执行**：执行前核对 JAR 与类仍是生成计划时的哈希，不同就不改动。先把原 JAR 完整备份：root 登录备份到 `/var/lib/lovelyres-java-updates/<编号>/`（旧记录用的也是这里），其他账号备份到自己主目录下的 `~/.lovelyhawk-java-updates/<编号>/`（普通账号不能在 /var/lib 下建目录）；两处都只有当前账号可读写。主目录是 `/` 或读不到的账号没有地方保存备份，不生成计划，页面说明原因。在同目录副本上更新这个类。`jar` 会把更新后的归档写成新文件，所以要先恢复原 JAR 的属主与权限，做不到就不换入（普通账号不能把文件交给其他账号：这时回执写明“这个 JAR 属于其他账号”，并删掉为这次准备的备份）；再解出来核对与所选文件一致，然后原子替换。替换后再独立回读一次（哈希、类、属主与权限），核对失败就用备份恢复。扩展属性、ACL 与 SELinux 标签不在核对范围内。
7. **记录与恢复**：每次替换都留下记录（本机 `data/` 中的 Java 历史与操作日志）。“恢复原 JAR”同样先出计划、再确认；只在 JAR 仍是当初替换后的样子时才恢复，之后被别人改过就不覆盖；恢复后核对内容、属主与权限都与原 JAR 一致。

## JDK 工具从哪里来

SSH 执行的命令不读登录配置，所以 `/etc/profile` 或容器镜像自己的环境变量放进 PATH 的 JDK，`command -v` 看不到，尽管主机上的 JVM 正是从它启动的。这时不能把“找不到”说成“只装了 JRE”。

工具先在 PATH 里找；找不到时，到运行中 JVM 的 `java` 所在目录里找。这个目录取自内核给出的 `/proc/<pid>/exe`，不取命令行。这样找到的工具，只有当它本身、它所在的 `bin` 目录和 JDK 主目录都属于 root 或当前登录账号，并且组和其他人都不能写时才会使用；任何一项读不到属主或权限，也当作不可用。否则，一个从别人可写的目录启动的 JVM 就能决定本工具以当前账号执行什么程序。找不到可用的 `jar` 时，页面列出常见原因，并禁止打开 JAR。

## 尚未覆盖

- 普通账号经 sudo 提权替换：没有提供，也没有实测。
- 只装 JRE 的主机，Alpine/BusyBox 的 `ps`/`ls`/`stat`，RPM 系发行版，JDK 8/11/21，以及其他 CPU 架构。
- Tomcat 等应用服务器的真实 Web 应用：`WEB-INF/lib` JAR 什么时候会被关闭、替换后热部署会不会自动重载，都还没有实测。
- Spring Boot 可执行 JAR 里嵌套的 JAR（`BOOT-INF/lib/*.jar`）不能直接替换其中的类；`BOOT-INF/classes/` 下的类可以。
- 只能整类替换，不提供按方法选择；也不使用 JVM 的类重定义（`jcmd`、agent），这些工具只在扫描里报告是否可用。
- 以上都只在容器中运行过，不涉及内核、启动或服务管理。
